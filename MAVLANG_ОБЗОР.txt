MAVLANG — ПОЛНЫЙ ОБЗОР ЯЗЫКА И ЭКОСИСТЕМЫ (v0.5, октябрь 2026)
----------------------------------------------------------------

MavLang — мой собственный язык программирования низкого уровня.
Расширение файлов: .mavl. Репозиторий: github.com/mavrodikomsd-eng/MavLang

Идея: максимальная простота синтаксиса в духе Rust/Zig, но без сложности
borrow-checker и макросов. Пишешь на MavLang — получаешь быстрый нативный .exe.

======================================================================
1. КАК ОН УСТРОЕН (ГЛАВНАЯ ИДЕЯ)
======================================================================

MavLang — это язык-транспилер. Полного компилятора с кодогенерацией в
машинный код у него нет (пока); вместо этого компилятор `mavc`
превращает .mavl в Rust, а Rust собирает ассистент — rustc/cargo:

    source/main.mavl  ──mavc──►  intRs/src/main.rs  ──cargo/rustc──►  mavapp.exe

Отсюда три следствия:
- Любая программа на MavLang работает на скорости нативного Rust-кода —
  потому что после транспиляции это И ЕСТЬ Rust.
- Ошибки типов ловит borrow-checker rustc на этапе компиляции.
- Ошибки компиляции маппятся обратно в строки исходника .mavl,
  поэтому пользователь НИКОГДА не видит сгенерированный Rust —
  для него это выглядит как самостоятельный язык со своим компилятором.

Компилятор mavc написан на чистом Rust (~1200 строк), без внешних
парсерных библиотек. Устанавливается глобально: cargo install --path compiler

======================================================================
2. СИНТАКСИС ЯЗЫКА
======================================================================

Общий дух: Rust минус сложность. Один стейтмент = одна строка,
каждый заканчивается точкой с запятой (кроме блоков { }).

ПОДКЛЮЧЕНИЕ ТОЧКИ ВХОДА (обязательно):
    fn main() {
        print("hello");
    }

Типы (система типов полностью соответствует Rust):
    i32, u32, i64, u64, f32, f64, bool, char, String, str, Vec<T>, [T; N]

Переменные:
    let x: i32 = 5;          // неизменяемая, с явным типом
    let mut y = 10;          // изменяемая, тип выводится компилятором

Функции:
    fn квадрат(n: i32) -> i32 {
        return n * n;
    }
    // идентификаторы могут быть и кириллицей — Rust это позволяет

Условия и циклы:
    if n > 10 {
        ...
    } else {
        ...
    }

    while n > 0 {
        n = n - 1;
    }

    for i in 0..3 {          // диапазон 0,1,2
        ...
    }

    match коде {             // полноценный match Rust доступен транзитом
        1 => print("один"),
        _ => print("многое"),
    }

Структуры и перечисления:
    struct Точка {
        x: i32,
        y: i32,
    }

    enum Направление {
        Вверх,
        Вниз,
    }

    impl Точка {
        fn новая() -> Точка {
            return Точка { x: 0, y: 0 };
        }
    }

Владение, ссылки, unsafe — всё если как в Rust (см. режимы памяти ниже):
    let p: *mut i32 = a.as_mut_ptr();   // реализовано в --mem=manual

Строки и векторы:
    transpile pass:  одна строка .mavl ≈ одна строка .rs —
    поэтому транспиляция предсказуема и отладка проста.

======================================================================
3. СТАНДАРТНАЯ БИБЛИОТЕКА (24 функции, ВСЁ БЕЗ ИМПОРТОВ)
======================================================================

Все встроенные функции доступны из коробки, без use/import.
Транспилер раскрывает их в вызовы std Rust:

  ВВОД-ВЫВОД
  print(x)          печать; для Vec<T> автоматически формат {:?}
  input(промпт)     чтение строки с клавиатуры -> String

  ФАЙЛОВАЯ СИСТЕМА
  read_file(путь)   весь файл -> String
  write_file(путь, строка)      записать файл
  append_file(путь, строка)     дописать в конец файла
  exists(путь)      есть ли файл -> bool
  dir(путь)         список файлов в папке -> Vec<String>

  СТРОКИ
  len(х)            длина строки или вектора
  split(с, разделитель)   разбивка -> Vec<String>
  lines(с)          разбиение по переносам строк -> Vec<String>
  join(вектор, разделитель)     склейка -> String
  trim(с)           обрезать пробелы по краям
  upper(с)          заглавные
  lower(с)          строчные
  capitalize(с)     первая заглавная
  contains(с, под)  содержит ли подстроку -> bool
  to_int(с)         строка -> i32

  СИСТЕМА
  args()            аргументы командной строки -> Vec<String>
  arg(индекс)       i-й аргумент (0 = имя программы)
  env(имя)          переменная окружения -> String
  time_ms()         время Unix в миллисекундах -> i64
  sleep(мс)         пауза
  check(условие)    assert для тестов
  gui::window(текст) заглушка под будущий GUI (сейчас выводит метку)

Особенность print(): для скаляров и строк -> '{}', для векторов -> '{:?}'.
Пользователю не нужно это думать.

======================================================================
4. РЕЖИМЫ ПАМЯТИ (--mem)
======================================================================

Концепция языка — «эволюция от простого к низкоуровневому». Три режима:

  --mem=borrow   РЕЖИМ ПО УМОЛЧАНИЮ. Обычный Rust-стиль: владение, & и &mut.
                 Проверки borrow-checker — своего пока нет, делегирует rustc.

  --mem=arena    Расширение на будущее (bump-аллокатор). Сейчас заглушка.

  --mem=manual   разрешает unsafe-код: сырые указатели *mut T / *const T,
                 арифметику указателей через .offset(). Пример работающего кода:

                 fn main() {
                     let mut a = [10, 20, 30];
                     let p: *mut i32 = a.as_mut_ptr();
                     unsafe {
                         *p.offset(1) = 99;
                     }
                     print(a[1]);   // 99
                 }

Зарезервированные слова borrow/arena/manual — самодокументация режима.

======================================================================
5. ПРОЕКТЫ. МНОЖЕСТВО ФАЙЛОВ, ЗАВИСИМОСТИ
======================================================================

Структура проекта MavLang:

    мойпроект/
      source/*.mavl      исходники (main.mavl обязателен, стартовая точка)
      intRs/             вся Rust-кухня (генерируется, рук не трогать)
      target/debug/      готовый mavapp.exe
      target/release/    релизный mavapp.exe
      mavlang.toml       необязательный файл с зависимостями

Мультифайл: mavc склеивает ВСЕ source/*.mavl в один main.rs.
main.mavl идёт первым, остальное — по алфавиту. Ошибки маппятся в исходники.

Зависимости: крейты Rust добавляются через mavlang.toml:

    [deps]
    egui = "0.28"
    serde = "1"

mavc build мержит их в [dependencies] в intRs/Cargo.toml.
То есть программы на MavLang могут использовать всю экосистему крейтов Rust.

6. CLI КОМПИЛЯТОРА mavc
======================================================================

    mavc check                 быстрая проверка синтаксиса + транспиляция
    mavc build                 сборка: .mavl -> rust -> mavapp.exe
    mavc build --release       оптимизированная сборка
    mavc run                   собрать и сразу запустить
    mavc clean                 удалить сборки
    mavc watch                 демо-режим: следит за source/ (каждые 500 мс)
                               и автоматически пересобирает при сохранении
    mavc lsp                   LSP-сервер для редакторов

======================================================================
7. LSP-СЕРВЕР И РАСШИРЕНИЕ VS CODE
======================================================================

mavc lsp — минимальный Language Server Protocol сервер поверх stdio
(JSON-RPC), написанный с нуля:

- диагностика в реальном времени (нет fn main / дисбаланс скобок / ; хинты)
- автодополнение ~30 функций и ключевых слов со сниппетами
- hover-подсказки по API стандартной библиотеки
- textDocument/didOpen/didChange на пересчёт

Расширение VS Code (vscode-mavlang) ставится в
%USERPROFILE%\.vscode\extensions\mavlang-0.1.0\:
- подсветка синтаксиса .mavl (тёмная тема, код Consolas)
- клиент LSP — редактор=IDE прямо в VS Code

8. ВНУТРИ КОМПИЛЯТОРА: HOW IT'S MADE
======================================================================

Этапы работы mavc на каждый build:

1) collect_sources — собирает все source/*.mavl (main.mavl первым).

2) transpile_line — построчная транспиляция:
   - is_word_boundary: не срабатывает если имя встроено в другое слово
     (my_print( не превратится в принт);
   - fn_before: если перед именем стоит fn — это СВОЯ функция,
     встроенную не раскрываем (можно переопределять вообще любой Builtin);
   - микрозамены: print -> println! и т.д. (полная таблица есть);
   - FIXPOINT: транспиляция повторяется до 8 проходов, пока строка
     перестает изменяться — так работают вложенные вызовы
     print(len(split(строка, ","))).

3) combine_and_transpile — склейка с шапкой (режим памяти) и
   комментариями-маркерами «// <имя_файла>» перед каждым файлом.

4) map_rust_line_to_mavl — магия для UX: ошибки rustc вида
   «main.rs:12:5» пересчитываются в «source/main.mavl:5» — вычитая шапку
   и сопоставляя маркеры файлов. Пользователь видит СВОИ файлы,
   не сгенерированный код.

5) грузим cargo build --manifest-path intRs/Cargo.toml [...]
   и копирует mavapp.exe в target/debug или target/release.

Зависимости компилятора serde/serde_json — только для LSP.

======================================================================
9. ОГРАНИЧЕНИЯ (ЧЕСТНО)
======================================================================

- Своего borrow-checker нет — правила изучаются через rustc.
- Своей кодогенерации в машинный код нет — делегируется rustc.
- ОМео внутренние структуры ограничены: нет mod/крейтов внутри языка,
  крейты только через mavlang.toml.
- Для запуска нужен Rust toolchain в системе.
- gui::window пока заглушка.

10. ЭКСПЕРИМЕНТ ИИ: ОБУЧИЛ LLM ПИСАТЬ НА СВОЁМ ЯЗЫКЕ
======================================================================

Так как языка нет в интернете (в обучающих выборках его нет),
подготовка данных — интересная часть проекта:

- Модель: Qwen2.5-Coder-0.5B-Instruct (0.5 млрд параметров)
- Датасет: 252 примера (instruction/input/output) в ai/dataset.jsonl,
  все на языке, которого НИГДЕ нет в интернете
- Обучение: LoRA (r=16), 5 эпох, RTX 4060 Laptop 8GB — ~15 минут
- Loss: 1.74 -> 0.76

Результат на жёстком бенче (16 разнообразных задач):
- базовая модель: 0 / 16 корректных
- после LoRA:     14 / 16 (эвристическая проверка),
                  6-10 / 16 проходят реальный mavc build+run

Скорость: 22 tok/s (bf16, полный float-инференс без квантования).

Датасет сохранён и пригоден также для RAG-сценариев.
